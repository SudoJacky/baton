# 实现与验证记录

验证日期：2026-09-25。环境：Windows、Node.js 24.14.0、pnpm 11.25.0。

## 计划审批与四工具 worker（当前实现）

- 新计划默认只在发布时人工审批；先建齐子任务与代码仓库，批准后范围锁定。实现、独立验收、返工和计划收尾不再逐项审批。设置页提供可选的合入前审批，实际合入使用 merge 任务；冲突上报后冻结并通知人。
- 主 Agent 的 dispatch_task 原子准备身份、认领和写入锁，并返回任务绑定的 run_id。worker 使用 get_task、post_message、submit、review；MCP 自动续租。共享目录锁延续至独立验收结束，失效 worker 不能继续通过简化接口写入。
- SQLite v5 增加工作流计划标记、批准记录和 worker assignment。旧默认策略迁为 plan 模式，旧自定义策略保留 custom；旧任务不是新工作流计划，不被伪造成已批准，也不会因新计划门槛无法继续原手动流程。
- 四个包构建、完整 typecheck（含模板）通过；58 项测试通过（服务端 43，客户端 15）。新增用例覆盖唯一计划审批、依赖、原子派发、重复调用、审批范围、返工上限、旧 worker、停止/替换验收、合入开关与冲突、异步 Git 竞争，以及真实 v4 数据迁移。
- 真实 HTTP + Git + MCP stdio 验证：同一个 MCP 用 planner 派发两个身份的 worker，自动续租跨越两个短租约，频繁 get_task 不阻止续租；完整提交和独立验收成功，错误 SHA、脏目录及遗漏标准无法获批。
- 隔离内存数据库与临时 Git 仓库的浏览器验证通过：查看子任务并批准计划、批准后范围编辑入口禁用、合入审批开关保存并刷新保留、自定义规则切换、375px 窄屏。无 pageerror。[计划审批](../output/workflow-plan-approval.png)、[已批准](../output/workflow-plan-approved.png)、[设置](../output/workflow-settings.png)、[窄屏](../output/workflow-settings-mobile.png)。
- skill 入口精简为四工具 worker；编排和手动完整协议分别按需读取。官方验证器及 8 个高级接口 JSON 示例通过。
- 本机 4100 服务已在在线备份和实际数据库副本迁移预演后重启，schema 为 v5，当前策略为 plan、合入审批默认关闭；8 个既有任务的状态、负责人、仓库、冻结标识和全部写入锁逐项核对一致。全局已安装 skill 的四个文件完成备份与同步，源码和安装文件 SHA-256 一致。
- 限制：本轮没有启动真实 LLM 编码会话；dispatch_task 不启动模型，仍由主 Agent 使用宿主子 Agent 能力推进。CLI 单次请求没有自动续租器。服务不执行 Git 合并，merge 冲突必须由实际执行合入的 worker 报告。只有在主会话/执行者仍运行时才有自动推进，不能承诺停止主会话后仍在后台工作。

- 前端与服务端构建通过，服务端 34 项测试通过，改动文件通过 Prettier 和 diff 检查。浏览器使用独立内存数据库、随机端口与临时 Git 仓库，验证了空白原因拒绝、返回不提交、冻结且持旧版本锁的任务取消后释放锁、记录原因、移除异常待办，以及保留仓库文件和关联任务。待审批草稿取消后申请移出队列，随后通过页面成功创建同名的新任务；已完成和已取消任务不再提供取消入口。

这轮只更新技能与说明，没有修改服务端策略、全局 MCP 配置或实际看板数据，也没有让模型执行真实的编码、测试和合入闭环。下面的构建、类型检查与 47 项测试是此前功能实现的验证记录，本轮没有重跑这些检查。

## 当前实现：按任务选择仓库、职责角色与共享 MCP 会话

- 服务启动不绑定仓库。任务顶层 `repository` 接收服务所在机器的绝对 Git 工作树路径；跨仓库总计划可以留空，代码任务开工前必须确定仓库。
- 异步解析 Git 工作树根目录，同一仓库的子目录和路径别名共享写入锁；不同仓库的锁和提交校验独立。领取结果包含仓库，列表与自动认领支持仓库过滤。
- Dashboard 支持仓库输入、历史路径建议、仓库筛选、任务详情编辑，以及按仓库取得和释放人工写入权。CLI / MCP 共用相同 schema，不增加会话级仓库配置。
- 数据库升级到 v4。旧任务的仓库为空；仍持有的旧全局锁保留并阻止新的写入，人工检查原目录后显式释放，再补仓库并恢复任务。已有返工或产物的旧任务可由人补充仓库，历史产物保持不变；已绑定且开工后的任务不能换仓库。

- Dashboard 打开即用，默认使用配置中第一个人工参与者；去掉登录页、退出按钮和人工登录码流程，清理浏览器中的旧登录值。
- 初始化不生成任何人工凭证，移除 `human-keys`。旧人工 token / 摘要兼容读取但不参与鉴权，`migrate` 可清理这些字段。
- 配置只保存参与者资料与角色预设，不需要逐 Agent token 或环境身份。
- 角色不绑定工具或模型。参与者 API 和界面移除 runtime / model，`join` 只接收 handle / role。旧配置读取时丢弃这两个字段，`migrate` 可以清理；历史数据库列保留兼容，但不再参与业务读取或写入。
- 初始化或服务启动自动生成本机接入密钥，CLI/MCP 自动读取，不返回给模型。
- 一个 MCP 可同时服务多个逻辑会话。`join` 返回会话 ID，其他工具每次显式指定 `session_id`；不存在共享的“当前身份”。
- 会话 ID 与参与者映射持久化，MCP/服务重启或空闲后可恢复。`leave` 只结束指定会话，不释放任务或写入锁。
- 状态按实际请求更新；MCP 不发送后台心跳，也不在连接关闭时注销其他会话。页面使用“最近活跃 / 暂无活动”表述。
- 人工专属操作不暴露给 Agent MCP；带 Agent 身份的 HTTP 请求继续执行 Agent 权限检查，缺失或无效会话不会回退为人工身份。混合人工与 Agent 标识会拒绝。
- 免登录人工请求通过客户端自动添加的非秘密自定义请求头显式选择；严格校验完整 Origin 与本机 Host，不开放 CORS，禁止页面嵌入。正常浏览器跨站请求无法获得预检许可，普通表单也不能代发人工操作。
- 幂等迁移删除旧 Agent token 与人工凭证，保留已有本机密钥。已有 v3 会话升级到 v4 后保持有效；从更早版本升级需重新加入。
- CLI 支持 `join`、`--session`、`leave`；保留单次 `--as` 与可选启动包装器。README、角色说明、三个工具适配文档与使用技能同步更新。

这是一套单人本机可信协作模型：本机进程可主动调用免登录人工入口，审批不构成对有意绕过流程的 Agent 的安全屏障。会话 ID 用于协作归属，角色规则用于防误操作；强进程隔离需要操作系统边界。

3. 使用 Agent 身份直接访问 HTTP 也不能执行人工审批或人工锁操作。默认本地人工用户无需凭证即可审批，事件正确记为该用户；其他人工 handle 可显式选择。

6. 请求更新活动时间不增加心跳事件；90 秒无请求只改变活动状态，不使会话 ID 失效。
7. 结束一个会话不会使同一参与者的其他会话失效，也不清除其任务归属。
8. 无显式客户端头的人工写入、远端 Host、其他端口/协议/主机的 Origin、无效 Origin、跨站预检均拒绝；同源请求正常。

## 尚未实测与使用边界

- 尚未让真实 Codex/Claude 模型通过 Baton 跑完编码、独立验收、返工和合入闭环，也未在用户的 Codex App 全局设置中安装本轮 MCP 配置。已验证同一 MCP 的多会话协议行为；本轮技能的子 Agent 模拟演练不等于真实任务协作验证。
- 全局 MCP 配置示例见 `adapters/codex/config.example.toml`；未修改用户的 MCP 配置。个人目录中已安装的 Baton skill 已同步仓库参数说明。逐 Agent token 旧配置仍需按 README 执行 `migrate`。
- watch 不自动唤醒模型。桌面通知送达、macOS/Linux、tmux 和工具专属 hook 本轮未验证。
- 代码任务需要在 `repository` 指定真实 Git 工作树；不会自动合并多个 App worktree。本轮实际 Git 与浏览器验证均在 Windows 完成，未实测 WSL/Linux/macOS 路径与符号链接。
- 写入锁约束平台流程，不是 OS 文件权限隔离。

构建仍有 Zod PURE 注释提示，Node 24 有 SQLite experimental 提示；测试有 Git 全局 ignore 读取权限和行尾提示，均未导致检查失败。
